# Ordinary-shell and Claude reference runtime evaluation

A standalone Rust executable owns native PTY/process lifecycle for ordinary shells. Python retains authenticated WS/Plugin contracts, application routing, command wrapping, durable ownership and binary output presentation. Default execution is unchanged Python; explicit isolated-harness evaluation selection is `NAVIDE_ACR_EVAL_RUNTIME=rust-shell` with `NAVIDE_REGRESSION_ROOT` set. Selected-Rust failures never spawn a Python PTY. The Claude reference slice additionally composes native JSONL interpretation and its existing shutdown strategy below. Other complete agent integrations, crash recovery, packaging and CI are not delivered by these slices.

## Build and applicability

Build explicitly before tests: `cargo build --offline --locked --release --manifest-path native/navide-cli-runtime/Cargo.toml`. The evaluated host uses the already-installed Rust 1.99.0 macOS ARM64 toolchain and cached lockfile dependencies. Tests do not acquire dependencies or build a missing native executable. Native POSIX behavior is actually verified on macOS only; Linux source suitability is not execution evidence. Windows returns unsupported rather than presenting a fake PTY. No ConPTY, three-platform release readiness or adoption claim.

## Private protocol 1

Python starts one lazily initialized executable per backend with `--protocol 1 --runtime-generation <fresh-token> --owner-pid <backend-pid>`. `ready` reports actual PID, owner, generation, version/platform and PTY implementation. Python checks identity/readiness and records executable SHA256 plus OS creation time before native create. There is no socket, provider transport, generic broker or STT abstraction.

UTF-8 JSONL requests contain strictly increasing runtime-wide `id: rN` (positive u64), `runtime_generation`, `op`, and `args`; session operations add `session_id` and `session_generation`. A mismatched generation is rejected. Replies correlate ID with `ok/result` or structured `error {code, stage, message}`. Lifecycle/output events carry the two generations and session/pane/workspace identity. PTY output remains raw bytes in `data_b64`, with monotone `seq`, byte `offset` and `dropped_before`; frontend UTF-8 decoding remains production code.

Operations are `create`, `activate`, `write`, `interrupt`, `kill`, `resize`, `release`, `flow`, `state`, `cancel`, `ping`, and `shutdown`. Native creates publish an ownership receipt before Python confirms durable registration and successful outward create; activation prevents early output escaping routing. Exit and cleaned receipts report exact status, output watermark, root reap and survivor/unverifiable identities. Cleanup keeps bounded PTY reads active while waiting to reap a signaled root: a blocked PTY write must progress before termination can complete. These bytes retain the same bounded publication/drop accounting and precede the exit watermark. A natural early exit is reaped evidence, never a fabricated live process.

One bounded FIFO controller and independent native IO loop per live session preserve admitted write/control order. Request histories are a scalar counter; confirmed settled session views retain at most 256 entries. Python has at most 256 pending private RPCs; native control/session operation queues are bounded at 256. Incoming requests are bounded at 32 MiB and outgoing lines at 64 KiB (raw read chunks <=16 KiB). Native publication and Python presentation use 5-MiB per-session raw-byte caps with drop-oldest accounting, existing one-second reader pause ceiling and pending-input semantics (500-ms blocked notice). These are raw-byte budgets, not a promise that JSON/base64/record overhead has no memory cost.

Lifecycle/control may overtake data only privately. Python settles and drains/accountably drops the recorded output watermark before public exit or resize ACK. A per-session Python control transaction owns resize/redraw/reattach through public ACK and release of its operation-local token. Multi-session reattach acquires unique locks in sorted order. Native resize immediately rejects an already-held fence without draining/overwriting it or waiting behind a queued release. Cancellation preserves matching cleanup before unlocking. Resize seals the old-width prefix at native admission and holds subsequent reads until public ACK/release; ordinary output is not truncated with a short terminal-record read buffer. Public output/exit/resize shapes are unchanged, and scrollback is never cleared.

`ping.bookkeeping` exposes bounded verification counters: last request, live/settled sessions, workers, queued output bytes/max per session and nonempty output queues. These are not a public API or benchmark claim. Full lost-ACK/cancel/replacement/sidecar-death recovery belongs to a later evaluation slice.

## Claude reference (ticket 03)

`shared/agent-cli/claude.json` is the reference's declarative authority. `uv --project backend run python scripts/generate-claude-facts.py --check` checks typed TS/Python/Rust consumers without writing. Existing specs retain their public shape. Only explicit isolated evaluation composes `NativeClaudeReader`; default callers and all other vendor specs keep their existing readers. Discovery, session existence/cross-project search, resume command recognition and common prompt presentation remain Python. JSONL record interpretation is native; selected failures do not run the Python Claude parser.

`create.args.agent_key` is empty for an ordinary shell or `claude` for this reference. Native Claude uses its declared graceful=true, grace_s=3.0, defer_master_close=true, including force requests; ordinary-shell policy is unchanged. Python retains the wrapped shell command, env precedence/removal, credential/quota policy, per-vendor switch lock, rollback, MCP/skills/hooks config writing, login rewrite and application ownership. The report/GO handshake is retained in Python for the vendors that declare live-file discovery; Claude does not declare that capability, so no new Claude handshake is invented.

Private `observe` requests use the existing sidecar and runtime generation, with `{vendor, path, mode, checkpoint, seen, expected_anchor_b64, anchor_invalid}`. Process-unbound/settled observations use one lazily started history worker with a 256-request bounded queue, not the shared stdin admission loop. It retains request/runtime correlation and the existing worker-count/teardown deadline; it invents no live-session ownership and no filesystem-syscall cancellation guarantee. Modes are `usage`, `session_usage`, `activity`, and `turns`. A matching retained Claude PTY contributes its runtime/session/pane/workspace attribution and validates the session generation; historical observation is explicitly process-unbound. Rust opens the actual file and returns parser/path/file identity, native session/cwd, interpreted records and next cursor. Correlated `observation` parts carry consecutive indices and base64-encoded result bytes before a final reply declaring `observation_parts`; each wire record stays below 64 KiB. Full application result lists retain the baseline's potentially unbounded size; this is a wire bound, not a constant-memory parsing claim.

Python converts 512-byte checkpoint anchors to/from the existing BLAKE2b spelling but does not parse JSONL. Usage consumes only newline-complete records and retains the last 64 accepted call keys. Activity retains its separate physical-line high-water, including valid unterminated records and intentionally no reset on truncation. A decoded non-object activity record still fails, but its correlated observation parts carry the inherited physical-line progress before the final `ok:false` reply. Python validates parser/path/native session/runtime/ownership, an advancing high-water and unchanged prior non-marker keys, applies that progress, then propagates the first error. It neither returns the earlier partial events nor silently treats the exceptional record as successful corruption skipping. The next poll can reach the following completion.

Existing durable Python stores decide when checkpoints are committed, including shutdown drain. The PTY sweep awaits cleanup acknowledgment for retained ownership, including naturally exited roots, and checks errors after acknowledgment/event completion. Successful unregister precedes the fence return; waits are bounded. Observation remains available until the existing Python drain completes; backend-owned pipe EOF then terminates the sidecar.

Principal verification is `mise exec node@22.23.2 pnpm@10.0.0 -- pnpm test:run --project cli tests/cli/claudeRuntime.test.ts`: the production TS WS client, authenticated Python handlers/stores, the actual hashed sidecar and macOS native PTY. It covers child-observed production command/config/model/effort composition, native usage/activity/turn completion, durable checkpoint restart, persisted resume and owned cleanup. The selected missing-binary case must refuse without launching a child/Python PTY; it does not claim a native process ran. These functional cases execute in default `pnpm test:run` on their declared macOS host. The CLI catalog/reporter links their executed post-assertion receipts and required outcomes separately from frontend vendor-spec unit contracts.

`backend/tests/test_cli_runtime_claude.py` provides supplementary real Python-WS credential/re-wake/quoting/checkpoint/error-progress evidence; `test_cli_runtime_claude_parity.py` supplies native-protocol parity and wire-bound checks. Controlled external vendor data/executables and the optional sandbox credential-store boundary are the substitutes, not successful runtime/handler/parser behavior. Native-reader composition and correlated native receipts support Rust interpretation; there is no fail-on-legacy-parser tripwire. The old frozen-r2 handoff's claim of explicit Python-parser rejection is invalidated, not implemented retroactively. No actual Claude/provider execution, packaging, cross-platform adoption or benchmark result is implied.
