# Preserve vendor semantics behind shared Agent CLI Integration contracts

Use the existing Python integrations for all currently supported agent CLIs as the behavioral baseline for designing shared Navide contracts and reducing duplicate implementation. Localize vendor-native differences behind those contracts rather than requiring vendors to expose identical capabilities or observation mechanisms: forced uniformity would simplify callers by misrepresenting what an external CLI can actually do. Changes within an existing capability should stay local to that vendor's adapter, declaration and tests; only a genuinely new capability kind should require extending the shared contract.

This is an evaluation direction, not migration authorization. Rust is a candidate implementation choice; retaining Python remains a valid outcome. The evaluation does not require a separately delivered Python consolidation first: compare the redesigned Rust approach with the existing Python baseline, distinguishing combined design-and-language benefits from benefits attributable specifically to Rust. Applying the same design to Python is a fallback to consider if the Rust approach is not worthwhile. Credential and quota policies and injection policy/configuration-writing implementations remain outside this evaluation's migration candidates. CLI-specific command, argument and path composition are also candidates for Rust ownership: Python injection handlers may delegate these mechanics without moving their application policy or effects. Prefer established command and path abstractions over duplicated platform-specific string assembly, while preserving existing shell, launch and vendor-native semantics.
