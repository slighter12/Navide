# Agent CLI Runtime baseline inventory (G0)

Baseline: `f4e9fd50136ea84f38f99e3c96f2c924f21d244f`. This describes shipped integration behavior, not a new policy or a promise about future vendor versions. The complete reproducible declaration/fixture/case receipt is `.scratch/agent-cli-runtime-evaluation/evidence/t01/inventory.json`, generated by its adjacent `inventory.py`. It includes all backend dataclass fields, callable source locations, complete frontend declarations, all executable catalog cases and the historical catalog. No credential/quota callbacks are executed by that inventory.

## Membership and evidence boundaries

`backend/agent_team_backend/cli_vendors/registry.py`, the frontend `platform/plugin-shell/agents/index.ts`, and `tests/fixtures/cli-regression/catalog.json` agree on all 15 vendors at this revision: aider, antigravity, claude, codex, copilot, cursor, droid, grok, kilo, kimi, mcode, muse, opencode, pi, qwen. `terminal` is an ordinary shell, not a vendor. The registry/catalog equality and frontend executable contracts were actually checked; this is not a permanent count requirement.

The catalog's reader cases execute real Python readers, attribution, application sinks and durable checkpoint reconstruction against synthetic data, but call the watcher processing method directly. They are not evidence of live filesystem notification or a future Rust runtime. The launch cases cross authenticated WS and a native PTY using isolated executable shims. Transport cases additionally exercise Claude authenticated re-wake, OpenCode/Kilo HTTP push, Qwen input-file delivery, Codex interrupt and login injection exclusions. No live vendor/provider compatibility was measured.

### Capability integration evidence

- MCP is integrated for antigravity, claude, codex, copilot, cursor, grok, kilo, kimi, opencode and qwen. Aider/muse/pi have documented no MCP surface in the baseline; Droid is not wired and its native feasibility was not established. mcode's absent declaration alone proves no native limitation.
- Managed skills are supported and wired for antigravity, claude, codex, copilot, cursor, grok, kimi, muse, opencode, pi and qwen. Kilo/Aider explicitly lack a skills mechanism. Droid/mcode empty declarations are not independent proof of vendor incapability.
- Non-composer delivery is integrated for Claude (hook wait/authenticated re-wake), OpenCode/Kilo (loopback append/submit/clear TUI HTTP; Kilo password policy), and Qwen (submit records via input file). Others retain ordinary PTY delivery; absence is not universal native unsupported evidence.
- Installed lifecycle hooks are declared for Claude/Copilot/Qwen. Codex SessionStart is separate launch-local hook wiring and trust-screen fallback, not `install_hooks`; no trust bypass is authorized.
- Codex interrupt is ESC; undeclared interrupt uses the legacy Ctrl-C default. Claude declares SIGTERM-first graceful shutdown even for force requests on POSIX. Other vendors retain shared cleanup. Windows graceful Claude parity is not established by a POSIX signal test.
- Frontend bracketed paste: Claude/Codex/Droid/Antigravity/Grok/Kimi; Codex Shift-Enter uses its CSI sequence. Silence inference is declared for Kimi/Pi/Qwen. Permission/awaiting-screen recognizers exist for Claude/Codex/Antigravity/Aider; absent recognizers do not imply absent native permissions.

## Launch entries, mechanics and retained application responsibilities

| Entry / source | Current path and boundary |
| --- | --- |
| Renderer agent/shell pane and resume/rebuild | `platform/plugin-shell/agents/*`, `lib/cliModel.ts`, `lib/resume-command.ts`, renderer terminal composables and `src/renderer/src/composables/hostSurfacePorts.ts`; validates requested model/effort and resume identity, submits `terminal.create` through production WS. Restored Codex home identity survives pane changes. |
| Host AI terminal contribution | `src/main/plugins/aiTerminalCommand.ts` uses `agentPaneCommand.ts`, with per-pane arguments, model/permission selections. Host routes existing terminal WS operations and public `aiCli` events without widening caller authority. |
| Plugin `aiCli` spawn | `FrontendPluginManager.aiCliCommand` in `src/main/plugins/frontendPluginManager.ts` uses the same wrapped-command seam, then creates an owned terminal under capability checks. This is not unrestricted plugin process spawning. |
| MCP/user-coordinated agent opening | Existing authenticated `cli_open_agent` asks the owning window to spawn; account/permission decisions and launch report/GO ordering remain application policy. Invalid model/effort or unsupported integrated ID resume is refused before work. |
| Backend create/login/replace/resume | `ws_handlers.py::terminal_create`, app session checks, terminal service and osplat. Launch discovery/probes, per-generation cancellation, ownership, duplicate reap, injection and attribution registration precede or coordinate actual spawn; create ACK may precede a slow baseline scan. |
| Ordinary shell/direct command | Same terminal service and native PTY, no agent adapter. User shell text retains shell semantics; direct argv and wrapped command are distinct accepted shapes. |

`agentPaneCommand.ts` explicitly preserves POSIX login-shell `[shell, '-ilc'/'-lc', line]` versus Windows agent-pane plain text interpreted with CommandLineToArgvW rules. Windows recognized npm `.cmd` shims unwrap to node, unknown batch wrappers retain cmd handling. Existing hook/MCP/push/skills injectors append to the wrapped list's last element; substituting raw argv silently would collapse arguments. Host/runtime migration must agree on this representation, not silently concatenate a different one. The measurement intentionally chooses an isolated `/bin/bash` login-shell rather than sourcing a user's shell setup; Windows seam code is available but unexecuted here.

Python retains credential vault/live-home isolation, account switches, quota fetching/exhaustion/failover, permission checks, injection ordering/config writes, locks/rollback, launch GO/report, durable project/history/token/checkpoint persistence and recovery policy. Runtime mechanics are program/argv/shell serialization, cwd/env/path composition, PTY bytes/resize/interrupt, generation/lifecycle/tree identity, session interpretation and log observation. Moving mechanical composition does not move the policies or side effects.
